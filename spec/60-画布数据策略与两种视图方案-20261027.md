## 2. 数据模型（按你的理解）

```
组织（Organization）
  └─ 项目（Project）——必须有主责组织；可以有合作/参与组织
       └─ 任务（Task）——必须属于一个项目，是执行动作
```

- 组织可以没有项目；没有项目的组织是**候选名单**，灰着。
- 项目可以没有任务；任务可以没有截止日期，但**必须有项目**。
- 项目没有主责组织、任务没有项目 → 放「待归位」，不伪造关系。
- 组织、项目、任务都可以互相关联；关联由 Agent 先判断或你输入。

### 3.1 名单来源

1. **外部供应链研究底图**：297 节点里属于组织/公司/机构的 **225 个**全部进入名单；

不进入名单的：底图里 72 个“产品/软件/场景/终端型号”等非组织节点。

### 3.2 每个组织的一生

```
看到/研究到组织
  → 录入名单（灰、待核对）
  → Agent 自动初步研究：打标签、角色、候选关系
  → 仍灰、仍待核对
  → 有项目（主责/合作/参与）→ 直接实现（亮）
  → 或你点「确认这个组织」→ 亮
  → 或你「不要/归档」→ 移出名单
```

- **录入名单不等于确认**：名单里可以有很多你只是“看过、研究过、觉得未来可能合作”的组织。
- **有项目是硬证据**：组织一旦进入项目，直接实现，不再等确认。
- **Agent 的标签/关系都是候选**：标“Agent 判断”；你确认后才算事实。
- 你随时可以补组织、改标签、确认/否定；Agent 后续继续补研究。

### 3.3 每个组织的两个字段

- **来源**：你录入 / Agent 整理 / 外部研究；
- **确认状态**：已确认 / 待核对。

界面只做两件事：
- 待核对：灰 + 虚线边 + 「待核对」角标；
- 已确认/由项目实现：正常颜色 + 「由项目直接实现」或「你已确认」。

## 4. 关联规则

| 关联 | 来源 | 可信度 | 画法 |
|---|---|---|---|
| 组织—项目、项目—任务、任务依赖 | 对象字段 | 事实 | 实线 |
| 组织—组织（标签/角色相似） | Agent 初步判断 | 候选 | 虚线 + 「待判断」 |
| 组织—组织（共同项目） | 两个组织在同一个项目 | 事实 | 实线 + 标项目名 |
| 组织—组织（你确认） | 你或 Agent 带依据确认 | 事实 | 实线 + 依据 |
| 项目—项目、任务—任务 | 共享组织/任务/依赖/资料 | 候选或确认 | 虚线 → 实线 |

**标签只负责“可能有关”，项目才负责“真的有关”。**

每条关系都写：来源、状态（待确认/已确认/已忽略）、一句依据；组织之间的实线必须能点回具体项目。

## 5. 两种可视化（只保留这两种）

### A. 全网视图（默认）

- 节点：**组织 + 项目 + 任务**（核心三层）。
- 连线：结构关系实线；候选关系虚线；真实组织关系实线并标项目。
- 默认只展开：
  - 已由项目实现的组织；
  - 有项目/任务的组织；
  - 活跃度最高的前 5 个组织（沿用已有算法的排序）。
- 其余候选组织**折叠**成“N 个待核对组织”，点开才展开；不丢数据、不影响搜索/计数。
- 折叠/展开按第 6 节的已有活跃度算法，手动可覆盖。
- 顶部同一句数据说明：`组织 272（已实现 2 / 待核对 270）· 项目 3 · 任务 6 · 关系约210`。
- 页面有「展开全部候选」按钮；展开后是全部组织的全网图，候选仍是灰的。

### B. 生态视图视图

- 节点：**只有组织**；项目、任务不画成节点，放在右侧详情里。
- 组织按角色/标签/供应链位置分层；某合作方科技在核心。
- 连线：
  - 实线：共同项目产生的真实组织关系；
  - 实线：你确认的直接关系；
  - 虚线：只有标签/角色相似的候选关系；
  - 底图只作参考层，可开关，不计入已确认。
- 点组织 → 右侧看项目、任务、关系；点项目/任务 → 详情。
- 顶部使用**同一句数据说明**，和全网视图一致。

### 两视图同步

- 一套数据，两种摆法；
- 同一组织/项目/任务，在两边点开是同一详情、同一状态、同一计数；
- 任一视图确认/修改，另一视图刷新后立即一致；
- 切换视图不复制数据、不生成第二套关系。

### 旧页签

- 去掉「结构 / 关系 / 待确认」三个独立页签；
- 只留「全网 / 生态视图」；
- 「待确认」变成两视图里都有的徽标：`待确认 202`，点开逐条处理；
- 原来的按角色分组、全图、关系证据、展开并入两个视图，不丢功能。

## 6. 活跃度与折叠：用你 2026-10-23 的算法

已找到并原样采用：

- `画布活跃度算法-v2.1-20261023.md`（公式与三项确认）
- `活跃度调参-demo.html`（缺失字段的兜底：重要/紧急缺省 0.5、30 天半衰）
- `画布方案-v3.1-20261023.md`（“前 5”展示规则）

公式（不改）：

- 任务 `T = 0.35×状态 + 0.25×被依赖 + 0.20×推进衰减 + 0.20×重要紧急`
- 项目 `P = 项目权重 × (0.4×任务聚合 + 0.2×阶段推进 + 0.2×关系 + 0.2×重要紧急)`
- 组织 `O = 0.7×最高项目 + 0.3×其余项目 + 0.1×关系热度`
- 衰减：最近一次推进 30 天 ×0.5、60 天 ×0.25、90 天归 0
- 生态常态化项目任务聚合保底 0.35
- 重要/紧急由 Agent 判断，标「AI 判断」，你改后变「你确认」

折叠只用这个分数排序，不改公式：
- 有项目的组织 + 分数最高的前 5 个组织默认展开；
- 其余候选折叠成“N 个待核对组织”；
- 低缩放时只显示高活跃名称，低活跃收起；
- 手动展开/收起优先；折叠不影响数据/计数/搜索。
